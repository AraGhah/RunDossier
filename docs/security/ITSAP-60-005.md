# ITSAP.60.005 — Website security controls (Preframe / RunDossier)

This document maps [ITSAP.60.005](https://www.cyber.gc.ca/en/guidance/security-considerations-when-developing-and-managing-your-website-itsap60005) (July 2025) requirements to controls implemented in this repository.

## Threat mitigations

| Threat | Controls in this repo |
|--------|----------------------|
| **SQL injection** | Parameterized queries (`RunDossier/src/db.ts`); no raw user SQL; generic 500 responses (`safe-error.ts`) |
| **XSS** | CSP on API + landing; `containsMarkup()` on user text; HTML escape in emails (`delivery-email.ts`) |
| **CSRF** | JWT in `Authorization` header (not cookies); CORS allowlist; origin check on pilot token |
| **DoS / DDoS** | Rate limits per route (`rate-limit.ts`); body size cap 512kb; edge DDoS via Cloudflare (deployment) |
| **AitM** | HTTPS/TLS at edge; HSTS when `TRUST_PROXY` + secure request; TLS to Postgres (`pg-ssl.ts`) |
| **Malware** | Dependency audit in CI (`npm audit`); Docker non-root; no user file uploads on API |
| **Credential stuffing / brute force** | Auth rate limit; account lockout after 5 failures (`auth-lockout.ts`); pilot honeypot |

## Secure development & management

| ITSAP topic | Implementation |
|-------------|----------------|
| **Secure architecture** | API / DB / queue segregated; Postgres separate from app; redundant workers via pg-boss |
| **HTTPS by default** | HSTS headers; TLS termination at reverse proxy; `DATABASE_SSL` for DB |
| **Strong authentication** | JWT (HS256); API key exchange with timing-safe compare; secrets validated at boot |
| **MFA** | Not applicable to current machine-to-machine API model; document if user accounts are added |
| **Access control / least privilege** | JWT roles `admin` / `pilot`; admin routes behind `requireJwt`; intake admin-only |
| **Service provider assessment** | Documented in `SECURITY.md`; Supabase/Resend/Apify as sub-processors |
| **Input validation** | Per-route validation; `sanitize.ts`; length limits; UUID checks; LinkedIn URL regex |
| **Security configuration** | Security headers middleware; `X-Powered-By` disabled; directory browsing N/A (API) |
| **Session management** | Stateless JWT with TTL; `Cache-Control: no-store` on API; short pilot token (15m) |
| **Secure operations** | `security.txt`; audit log (`audit-log.ts`); structured logging; PII retention job |
| **Patch management** | Dependabot; CI `npm audit`; `npm run audit:deps` |
| **Security awareness** | This document + `SECURITY.md` vulnerability reporting process |
