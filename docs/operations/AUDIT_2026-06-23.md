## Purpose & main workflow
**Preframe/Dossier** is a productized B2B prospect-research service. Pipeline: client onboarding (Stripe +
Tally) → prospect intake → **research** (Apify LinkedIn + Apollo + podcasts) → **personalization** (Claude
ladder: Haiku→Sonnet→Opus) → **independent QA** (Gemini judge) → **delivery** (CSV emailed as attachment).
Ops run on pg-boss cron jobs; alerts + control via a Telegram bot. The `landing` site markets it and runs
the onboarding form.

## Issues by severity (with root cause, fix, status)

### HIGH
**H1 — 6 public tables had RLS disabled (anon read/write).** `telegram_updates, delivery_events,
workflow_runs, audit_events, onboarding_events, telegram_command_log` were exposed to the Supabase anon
key — including `audit_events`, the tamper-evident hash-chain log (anon-writable undermines it).
*Root cause:* tables created without `ENABLE ROW LEVEL SECURITY` (the other 18 had it).
*Fix:* migration **025** enables RLS on all six (no policies — they're server-only, written over the
backend's direct owner connection which bypasses RLS, exactly like the other 18 tables).
*Status:* **FIXED + verified (live)** — security advisor re-scan: **6 ERRORs → 0**.

### MEDIUM
**M1 — Per-prospect $0.25 cost cap was env-bypassable.** `PER_PROSPECT_COST_CAP` could be set arbitrarily
high. *Fix (prior session):* `effectivePerProspectCapUsd()` clamps to a hard $0.25 ceiling (env may only
lower it). *Status:* **FIXED**, logic verified (12/12 checks).

**M2 — pg-boss `job` table bloat.** `pgboss.job` holds **9,318** rows, ~99% `completed` (scheduler runs
every 5 min, etc.); only 15 old `failed`. *Root cause:* `new PgBoss({connectionString, ssl})` sets no
retention. *Status:* **RECOMMENDED, not applied** — changing the queue constructor is high-blast-radius and
I can't run it here to confirm. Add to `src/queue.ts`:
`new PgBoss({ ..., archiveCompletedAfterSeconds: 3600, deleteAfterDays: 3, maintenanceIntervalSeconds: 300 })`,
then confirm in CI. (Functionally harmless today; a scale/perf concern.)

**M3 — Pipeline edge cases (n8n_fixes.md).** Personalization occasionally dead-letters on a hard word-limit
or when the model returns markdown instead of JSON. *Root cause:* hard length gate + model formatting.
*Mitigation already present:* the Claude ladder retries with "return only JSON" and `parse-json.ts` is
tolerant (fences/prose/trailing commas, raw output preserved). *Status:* **OPEN (low frequency)** — make
length a soft QA signal; see `docs/operations/pipeline-verification/n8n_fixes.md` B2.

### LOW
**L1 — Function `search_path` mutable** on 3 of our trigger functions. *Fix:* migration 025 pins
`search_path = public`. *Status:* **FIXED + verified** (3 of 3 cleared; 5 remaining are pg-boss's own
functions — third-party, left as-is).

**L2 — Delivery is at-least-once.** If a send actually succeeds but the provider reports failure, the claim
is released and re-sent → possible duplicate email. *Status:* OPEN (accepted tradeoff; rare). The atomic
claim prevents the common double-delivery; this is only the network-partition edge.

**L3 — batch cost/delivered_at rollup not wired into WF5.** Fixed retroactively + helper added last session
(`recompute_batch_cost`); the delivery job should call it on finalize. *Status:* documented.

### Corrected prior finding (important)
**"CSV never reaches the client / not in Drive" was WRONG.** Re-reading `delivery.job.ts`: the CSV is built
in memory and **emailed as an attachment** (`attachments: [{ filename, content: Buffer.from(csv) }]`), with
an **atomic claim** (no double-delivery), a durable `deliveries` ledger, `delivery_events` audit trail, and
**release-on-failure retry** (no silent loss). Delivery is functional — it just isn't a Drive upload, which
was never the mechanism. Email actually sending still depends on a configured provider (Resend/Gmail).

## What was reviewed and found GOOD (verified by source review)
- **Auth** (`middleware/auth.ts`): JWT + role checks; legacy token via `secureCompare` (constant-time); generic 401s (no info leak).
- **Error handling** (`middleware/error-handler.ts`): logs real error + `requestId` server-side; returns only `{error:'Internal server error', requestId}` — no secret/stack exposure. Exactly the required standard.
- **Telegram webhook** (`routes/telegram.ts`): requires `TELEGRAM_WEBHOOK_SECRET` in prod, constant-time secret compare, validates `update_id`, fast-acks then processes async; dedup via `telegram_updates` table.
- **JSON parsing** (`utils/parse-json.ts`): robust, tolerant, preserves raw output on failure — not fragile.
- **Delivery** (`jobs/delivery.job.ts`): atomic claim, durable ledger, audit events, retry, internal-email exclusion, pure testable decision fns.
- **Deploy:** `Dockerfile` multi-stage, non-root user, healthcheck, prod env. `docker-compose.yml` sets SSL/CORS/proxy/healthcheck. `ci.yml` runs build+test+coverage+audit for both apps.
- **Frontend secrets:** `landing/.env` holds only `VITE_API_URL` (public), and is gitignored. No secret leaks into the client bundle.
- **DB consistency (live):** 121 prospects, **0** client-orphans, **0** orphan first_lines/ai_costs, **0** duplicate delivery recipients, **0** null-name prospects, **0** failed_jobs in 24h.
